# 11. Grafana

## What is it?

**Grafana** draws dashboards from data sources such as Prometheus. Each **panel** runs a query and shows the result as a number, a gauge, a table or a chart.

## Why this project uses it

Prometheus holds the numbers; Grafana makes them **readable at a glance**: "are all servers protected right now, and what is their score?" It is the screen you would put on the wall of an operations team.

**Alternatives:** Prometheus' own graph page (fine for queries, not for dashboards), Kibana, Datadog dashboards. Grafana is the standard companion of Prometheus.

## How it works: provisioning as code

Nothing is clicked together by hand. At start-up, Grafana reads:
- **Data sources** from [`lab/grafana/provisioning/datasources/datasources.yaml`](../lab/grafana/provisioning/datasources/datasources.yaml):

```yaml
datasources:
  - name: Prometheus
    uid: prometheus
    type: prometheus
    url: http://prometheus:9090
    isDefault: true
    editable: false
```

- **Dashboards** from JSON files, via [`lab/grafana/provisioning/dashboards/dashboards.yaml`](../lab/grafana/provisioning/dashboards/dashboards.yaml), which points at `/var/lib/grafana/dashboards`. The dashboard is [`lab/grafana/dashboards/server-baseline.json`](../lab/grafana/dashboards/server-baseline.json) and is set as the home page.

Because the dashboard is a file in Git, it is reviewed and versioned like code; CI checks it is valid JSON.

**Access in the lab** ([`lab/compose.yaml`](../lab/compose.yaml)): anonymous users get the **Viewer** role; the admin password is generated by `scripts/lab-up.sh` into `.lab/grafana-admin-password` (git-ignored) and passed to Grafana as a Docker secret (`GF_SECURITY_ADMIN_PASSWORD__FILE`), never written into the compose file. Ports are bound to `127.0.0.1` only.

## The dashboard: "Server baseline: security & health"

| Row | Panel | Query (simplified) | Reads as |
|---|---|---|---|
| Security posture | Servers reporting | `sum(up{job="node"})` | how many servers Prometheus can scrape |
| | Lynis hardening index | `lynis_hardening_index` | bar per server; red < 60, orange < 75, green ≥ 75 |
| | Addresses banned now | `sum(fail2ban_banned_current)` | orange as soon as anyone is banned |
| | Firing alerts | `count(ALERTS{alertstate="firing"}) or vector(0)` | `or vector(0)` shows 0 instead of "no data" |
| | Days since last audit | `max((time() - lynis_last_run_timestamp_seconds) / 86400)` | orange after 7, red after 8 days |
| | Security services | `node_systemd_unit_state{state="active"}` as a server × service grid | green 1 = running, red 0 = stopped |
| | Baseline version | `server_baseline_info` as a table | which baseline version and OS each server runs |
| Attacks | fail2ban: SSH failures and bans | `fail2ban_failed_current`, `fail2ban_banned_current` | the brute-force test shows up here |
| Resources | CPU busy, Memory used, Network received | node_exporter basics | is the server healthy |

## Try it

1. Open <http://localhost:3000>. The dashboard is the home page.
2. Run the brute-force exercise from chapter 5 and watch "Addresses banned now" and the fail2ban chart (the textfile timer runs every minute, so allow 1–2 minutes).
3. Stop a protection and watch the "Security services" grid turn red:
   ```bash
   docker compose -f lab/compose.yaml exec db-01 systemctl stop fail2ban
   # after ~2 minutes SecurityServiceNotRunning also fires in Prometheus (Alerts tab)
   make harden     # starts it again
   ```

## Common mistakes

- **Building dashboards by clicking** and never exporting them: they are lost with the container.
- **Panels that show "No data" instead of 0:** use `or vector(0)` where 0 is the honest answer.
- **Default `admin/admin` password**, or a password committed to Git. Use a generated secret.

## Check yourself

1. Where does Grafana get the dashboard from when the container starts?
2. Why does the "Firing alerts" query end with `or vector(0)`?
3. How is the Grafana admin password kept out of the repository?

<details><summary>Answers</summary>

1. From the provisioning config, which loads the JSON file `lab/grafana/dashboards/server-baseline.json` mounted read-only into the container.
2. When nothing is firing, `count(...)` returns no data. `or vector(0)` turns that into a clear 0.
3. `scripts/lab-up.sh` generates it into `.lab/grafana-admin-password` (git-ignored), and compose passes it as a Docker secret that Grafana reads through `GF_SECURITY_ADMIN_PASSWORD__FILE`.
</details>
